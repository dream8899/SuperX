将方括号内容替换为实际值。Instagram 为主渠道；TikTok、YouTube 和其他
yt-dlp 支持的平台沿用同一目录、状态和安全规则。

## 可复制任务指令

```text
请将下列公开或已获授权的社交媒体账号/视频，安全增量归档到：
[绝对输出目录]

账号清单：
- [账号或主页 URL]｜页面作品数估计：[数量/未知]｜备注：[内容或优先级]
- [账号或主页 URL]｜页面作品数估计：[数量/未知]｜备注：[内容或优先级]

执行要求：
1. 每个博主建立独立子目录、metadata.tsv 和 README.md；渠道根目录维护
   channel_index.md，方便后续只下载新增作品。
2. 任务开始前先盘点：页面显示数、当前可发现唯一短码数、metadata 唯一
   短码数、已验证文件数、重复记录、明确失败项和估计可归档范围。页面显示
   数仅作为上限，不要求强行下载到该数字。
3. 登录态只允许辅助发现规范作品 URL/短码，严禁进入下载链路。Instagram 主页优先
   使用 Instaloader 匿名有限发现；已存在 metadata 时遇到首个历史短码就停止。若匿名
   发现不可用，再从 Computer Use、Chrome/CDP、Playwright、Kimi WebBridge、同类扩展桥
   或人工导出中选择一种。YouTube 等仅在已验证 collection extractor 存在时使用 yt-dlp
   原生主页/频道发现。所有媒体下载仍使用 yt-dlp `--no-cookies`。
4. 每个新任务/账号先下载5条试批，全部通过 ffprobe 且没有挑战、限流或连续
   网络错误后，后续每批最多20条。单进程执行，失败一条即停止该批。
5. 浏览器发现以滚动主页一次收集当前可暴露的短码为主：每次滚动一个视口，
   随机等待3–8秒，保存新增 canonical URL；连续两轮无新增、到达页面末尾或达到
   上限即停止。弹窗翻页只作最多5条补漏，不得快速连续点击。禁止刷新循环；以
   URL、页面快照和短码集合变化为操作证据。
6. 每批结束立即更新 metadata、README、channel_index、下载归档和失败状态。
   再次访问时按唯一短码/媒体 ID 对比，只把新作品按时间倒序加入队列。
7. 对隐藏、删除和失败内容分类：未由页面/API 暴露为 not-discovered；下一页
   为空或 more_available=false 后的差额为 not-discovered-or-unavailable；已暴露
   但媒体为空/禁止访问，冷却后仅重试一次，仍失败则为 inaccessible-or-deleted。
8. 自动检查 yt-dlp 更新，但只能在没有活动下载时、经用户授权后升级。升级后
   先跑测试、1条试下载和 ffprobe，再恢复批量任务。
9. 全部当前可发现内容处理后，汇总真实可归档数量、有效文件数、重复/失败/
   未暴露数量和候选经验。候选仅写入隔离学习区，不得在任务运行中更新 Skill、模板、
   脚本或默认规则；晋升必须另开受控维护任务并取得人工批准。
```

## 输出契约

根目录：

```text
[输出目录]/
├── [channel]/
│   ├── creator_registry.tsv
│   ├── channel_index.md
│   ├── [creator-1]/
│   │   ├── README.md
│   │   ├── metadata.tsv
│   │   ├── batch-log.jsonl
│   │   ├── .download-archive.txt
│   │   └── *.mp4
│   └── [creator-2]/...
```

每个账号的 `README.md` 至少记录：

- 主页 URL、平台、内容概括和页面显示作品数；
- 最近检查时间、发现记录数、唯一短码数和已验证文件数；
- 最近批次大小、使用方法和增量更新锚点；
- 重复记录、明确不可访问项、未暴露差额及下次操作建议。

`metadata.tsv` 每个作品一行，推荐字段：

```text
序号	发布日期	短码或媒体ID	视频地址	标题	状态	文件名	时长秒	文件字节	发现时间	下载时间	备注
```

最低要求是永久保存唯一短码/媒体 ID 和规范视频地址。若旧版下载脚本只接受
四列清单，可保留兼容清单作为下载输入，但必须在 README、info.json 或独立
状态表中保存规范地址，升级脚本后再迁移；不要直接增加列导致旧脚本解析失败。

`channel_index.md` 每个账号一行，推荐字段：

```text
账号 | 主页URL | 页面显示数 | 已发现 | 唯一短码 | 已验证文件 | 不可访问 | 未暴露/未知 | 最近检查 | 下次动作
```

## 启动盘点公式

对每个账号计算：

```text
已发现唯一数 = metadata 中唯一短码/媒体 ID 数
已验证唯一数 = 能映射到唯一短码且通过 ffprobe 的文件数
待下载数 = 已发现唯一数 - 已验证唯一数 - 终态不可访问数
未暴露估计 = max(页面显示数 - 已发现唯一数, 0)
```

文件数不能代替唯一作品数：回退文件、重复命名和后处理副本会抬高文件计数。
只统计账号目录顶层的源归档文件，排除 remix、发布和审核输出。

## 方法选择与升档

1. 单视频 URL：直接 yt-dlp 无 Cookie，验证后写入状态。
2. Instagram 主页：先用匿名 `discover-instagram`，范围限制为试批5条；增量任务
   读取历史 metadata 并在首个已知短码停止。
3. 已验证支持的其他平台主页/频道：使用 yt-dlp 原生 profile/playlist。
4. 匿名发现失败：选择可用浏览器发现器或人工导出，运行 `normalize-discovery`
   形成统一 URL 清单，不下载浏览器媒体，不导出登录会话。
5. 试批5条全部成功：下一批上限20条；任一失败则停止，不自动升档。
6. 已知直接 URL：后续下载不再重复访问主页。

## 增量更新算法

1. 读取 channel_index、README、metadata 和下载归档。
2. 单次访问主页，收集当前可见短码/媒体 ID，并规范化 URL。
3. 与历史唯一 ID 集合比较；只保留未知 ID，按新到旧排序。
   历史集合必须合并 metadata.tsv、.download-archive.txt 和已验证文件名中的
   shortcode；旧批次可能有 metadata/文件但遗漏归档行，不能因此重复下载。
4. 先跑5条试批；成功后每批最多20条，逐批更新状态。
5. 连续无新短码、公开分页结束或触发安全停止条件时结束本次访问。
6. 写入最近检查时间和下次增量锚点。不要把页面显示数当完成条件。

## 安全停止条件

立即停止当前来源：429、checkpoint、challenge、登录要求、验证码、连续超时、
页面临时无法加载、公开分页为空、媒体空响应或 ffprobe 无效。不要通过快速刷新、
代理轮换、User-Agent 轮换、Cookie 导出或并发增加来绕过。

## 完成判定

当前一轮完成需要同时满足：

- 所有当前已发现且可访问的唯一作品均有验证文件；
- 其余已发现项已有终态分类和证据；
- 页面显示数与可发现数的差额被标记为估计值，而非漏下载断言；
- 每账号 README、metadata 和 channel_index 已同步；
- 没有运行中的下载进程、未处理临时文件或未记录错误；
- 方法变化、验证结果和安全经验已写入候选记录；未自动改写 Skill 核心。
