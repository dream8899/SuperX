# SuperMedia 资产中心：需求与边界

## 目标

为 `superdown88 → super-video-mix → super-upload` 提供一个不依赖 AI Agent 的本地
入口：一键更新统一资产库，并在浏览器中查看素材、血缘、发布与待处理风险。

## 用户与场景

- 操作者下载或处理完一批素材后，双击一次即可将变化写入事实源。
- 操作者在计划发布前查看某博主、渠道或账号的历史使用情况。
- 操作者对未知血缘的历史 Remix 人工复核后，补全来源；未复核的资产继续 HOLD。

## 功能需求

1. 自动发现真正的渠道目录：仅扫描直接包含 `博主/metadata.tsv` 的目录。
2. 一键更新必须按顺序执行：独占锁 → SQLite 备份 → 增量同步 → 审计 → 报表导出 → 写入本次更新结果。
3. 管理台必须只绑定 `127.0.0.1`，不发起网络请求，不上传素材或数据库。
4. 管理台展示：总数、博主资产地图、最近发布、HOLD 清单、最近更新结果。
5. 管理台仅提供两类写操作：更新资产库、人工补全单个资产血缘。
6. 血缘补全必须填写已有文件、已登记 `source_key` 和至少 8 字符核验依据。
7. SQLite 是唯一事实源；JSONL 为审计镜像；TSV/JSON 是可再生报表。界面禁止直接写表。

## 非目标

- 不在此应用中下载、Remix、自动上传或公开发布。
- 不保存浏览器 cookie、登录态、平台账号密码或任何凭据。
- 不自动解除 HOLD，也不自动允许同源重复发布。

## 成功标准

- 首次和后续更新均可在不启动 Agent 的情况下完成。
- 同时运行两个更新时，后一个明确失败，不产生并发写入。
- 更新前存在可恢复 SQLite 备份；失败可依据备份恢复。
- 上传 Skill 继续以同一数据库的 `reserve-manifest` / `complete-manifest` 为准。
