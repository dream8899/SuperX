# SuperVideoMix 避坑与验收指南

## 本地去重中的哈希、感知指纹与元数据

- SHA-256/MD5 是文件字节级标识；重新编码或清理元数据后自然会变化。`md5-rotate` 通过容器元数据 remux 让新文件 MD5/SHA-256 与源不同，这是新字节的派生值，不是把哈希改成指定值；画面、声音与感知指纹不变。
- `fingerprint` 使用跨时间采样的基础视频感知指纹生成 `likely/possible/distinct` 候选组。它是本地分类证据，不是平台信号；候选组只进入人工复核，不能自动删除。
- 推荐顺序：`normalize`（编码兼容化）→ 可选 `metadata`（移除非内容标签/章节）→ `fingerprint`（重算报告）。源文件始终保留。
- 轻微调色、镜像或裁切可能仍被感知指纹归入候选组；这正是“找相似素材”的用途，不应把它解释为规避平台检测。

## 先执行的固定门禁

1. 确认内容为自有或已获授权；涉及水印、字幕、品牌标识时确认编辑授权与区域。
2. 用绝对路径指定输入和新的输出目录；源文件与最终成品绝不共用路径。
3. 先运行 `analyze` / `dedupe` / `plan`，先审查计划；只有用户批准后才运行 `apply`。
4. 执行后运行 `verify`；只在 `status=verified` 后交付或清理中间物。

## 批量素材的成功路径

```text
discover → exact dedupe → analyze → plan → preview/review → apply → verify → manifest/copy → archive
```

- 精确去重仅以 SHA-256 判定；不要把镜像、裁边、调色称作去重或平台规避。
- 无效片尾必须至少由黑屏、静音、低细节、静帧或重复中的多项证据支持；有疑义时保留并标记复核。
- 多主题长视频先运行 `split_multitheme_video.py`，查看联系表和切点预览。不得按整数秒、文件名或账号主题盲切。
- 每个拆分段都要看开头、中段、结尾代表帧，并建立 `filename → visual_subject → copy` 映射。
- 只有 `exact` 或人工确认的 `reviewed_category` 可以进入成品清单。`category_only`、空主题和纯序号必须 HOLD，不能生成“可发布”命名或文案。

## 命名与发布文案

- 文件名必须描述实际画面，不包含 `remix`、`翻新`、泛化的“主题变形玩具”等处理标签；批次父目录可保留处理标识。
- 命名、视觉核验表、发布文案和实际文件必须逐条一一对应；总数、文件名和目录必须一致。
- 发布文案默认以 `.txt` 交付：每个视频独立一份，子目录有索引汇总，批次根目录另有总汇总。
- 中文和 English 必须独立成段，不要在一句内夹杂语言；保留原始英文文案作为来源字段。
- 画面主体不确定时，文案只描述已核验的类别并标记 `reviewed_category`，不能编造国家、人物、建筑或型号。

## 处理参数的安全顺序

推荐顺序：`trim → authorized removal → crop/fit/fill → mirror/flip → color/filter → denoise → sharpen → speed → encode → verify`。

- `fit` 保留全部画面并补边；用户只说“转 9:16”时，不要默认 `stretch`。
- `fill`、水平镜像、调色、滤镜、降噪、锐化、变速都需要预览；`stretch`、垂直/双向反转和大区域清理属于 high risk。
- 3:4 顶部对齐裁切前必须运行 `crop_3x4_preflight.py`，审查红线预览；不适合的素材改为轻度放大或保留原比例。
- 固定小区域可使用获授权的 `delogo`；移动水印、运动背景或大面积字幕应路由到 VSR 类后端，不要反复堆叠 `delogo`。
- 降噪永远在锐化之前；变速必须同时改变视频 PTS 与音频 tempo，禁止用 `-shortest` 掩盖不同步。

## 输出目录位置

- **翻新输出必须放在源文件夹下作为子目录**，不能放到上级目录或与源目录平级。用户期望在源文件旁边直接看到 `翻新_YYYY-MM-DD/` 或类似命名的子文件夹。
- 示例：`源目录/2026-07-19_xxx__6段精准拆分/翻新_2026-07-26/`
- 3:4 裁切等二次处理同样放在源目录下，新建独立子文件夹（如 `翻新_2026-07-26_3x4_crop/`）。

## 文件与清理

- 不删除或覆盖源视频；任何覆盖都需要用户明确授权。
- 审批前保留分析、计划、预览和筛选清单；验收后将中间 JSON 移到批次归档或系统废纸篓，而不是不可恢复删除。
- 清理前确认每个 `apply` 均已 `verified`，并保留最终视频、文案、视觉核验映射与处理报告。

### 清理清单（逐项核对，不可跳过）

每批处理完毕后必须检查以下所有项：

| 清理项 | 位置 | 安全处置 |
|--------|------|----------|
| 分析 JSON | 输出目录 | 验收后移入批次归档或系统废纸篓。 |
| 计划 JSON | 输出目录 | 验收后移入批次归档或系统废纸篓。 |
| 执行 JSON | 输出目录 | 验收后移入批次归档或系统废纸篓。 |
| 去重报告 | 输出目录 | 验收后移入批次归档或系统废纸篓。 |
| 关键帧预览 | 源目录 | 验收后将 `preview_frames/` 整个目录移入系统废纸篓。 |
| 3:4 预判目录 | 源目录 | 用户批准、批次执行完成后，将 `*_preflight/` 整个目录移入系统废纸篓。 |

**实际踩坑**：多次遗漏 `preview_frames/`（关键帧提取产物）和 3:4 preflight 目录（含预览图和 TSV），被用户提醒后才补清。预判目录在用户批准并执行完毕后即可清理，审批依据的内容在处理报告中已有体现；优先移动到废纸篓，避免不可恢复删除。

## 常见失败与处理

| 现象 | 原因 | 正确处理 |
| --- | --- | --- |
| `OUTPUT_EXISTS` | 输出路径已有文件 | 生成新输出路径；不覆盖。 |
| `INPUT_HASH_MISMATCH` | 计划后源文件变化 | 重新分析并重新生成计划。 |
| `PREVIEW_NOT_APPROVED` | 视觉变化未审批 | 展示预览，取得确认后重建/执行计划。 |
| `HIGH_RISK_NOT_APPROVED` | 高风险操作未显式批准 | 保持计划状态，不能绕过门禁。 |
| 文案与画面不符 | 从系列标签或 OCR 片段反推内容 | 回到代表帧核验，重建映射、文件名和文案。 |
| 同一变形过程被拆成多段 | scene/dHash 把展开动作、快速手势或遮挡当成新主题 | 对 ≤5.25 秒局部段取切点前后四帧；同一主体、标签和动作目标则移除切点，从原片重建并完整解码验证。 |
| 批次 JSON/TSV 杂乱 | 将机器报告当交付物 | 将最终人类交付统一为 `.txt`；保留必要证据文件。 |
| Windows 找不到 FFmpeg | `ffmpeg/bin` 未在 PATH | 新开终端后运行 `ffmpeg -version`，仍失败则使用绝对路径或修正 PATH。 |
| 输出放到源目录外面 | Agent 默认在父目录创建输出 | **必须**在源目录下建子文件夹作为输出；用户期望翻新产物跟源文件在一起。 |
| 中间文件忘记清理 | 清理步骤不全 | 对照上方清理清单逐项执行；先写处理报告再删中间文件。 |
| `preview_frames/` 残留 | 提取关键帧后未删除 | 清理清单第 5 项；在最终清理时删除。 |
| 3:4 preflight 目录残留 | 预判执行后未清理 | 用户批准+批次执行完毕即可删除整个 `*_preflight/` 目录。 |
| PIL/OpenCV 不可用（macOS） | macOS 默认无 Python 图像库 | 不需要安装。用 `ffmpeg` 提取帧、`sips`/`ffprobe signalstats` 分析图像特征。 |
| Python 命令在 Windows 上是 `python` | Skill 内统一用 `python3` | Windows Agent 需先确认 `python3` 可用，否则创建别名或直接改用 `python`。 |
| 视频已 1080×1920 再用 `fit 1080x1920` | fit 对同分辨率是恒等操作 | 这不是错误，但 zoom/crop 才是实际变换；在报告中说明即可。 |
| 废片尾只有静音单一证据 | 阈值分析不足 | 保守保留，标记 `uncertainties`；不自动裁切。实战中 `suggested_cut_at=8.3s` 被跳过。 |
| 提亮需求无法用预设满足 | `natural` 等预设不改变亮度 | 使用 `--color custom --color-params '{"brightness": 0.1}'`（+10% 亮度）。 |
| preflight 扫描了翻新输出 | 源目录下有上一批的 mp4 产物 | preflight 会扫描目录内所有 mp4；在筛选清单中只关注源文件即可，翻新产物可忽略或提前移走。 |
| 3:4 裁切"人工复核" | 底部裁除带运动比高 | 向用户展示风险分和原因，让用户决定；用户确认后即可执行。实战中 Argentina（0.88 运动比）照常裁切无问题。 |
| `--safe-zoom` 锚点忘指定 | 默认 center 可能裁掉边角主体 | 去水印用 `--zoom-anchor top-left`；常规放大用 center。1.1× 属中风险，必须 `--approve-preview`。 |
